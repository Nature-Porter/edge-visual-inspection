# Timing and quality protocol

`model_gpu_ms` uses synchronized CUDA events on the user stream enclosing ORT inference. `pipeline_ms` starts after image decode and includes preprocessing, transfer, model and postprocessing. `decision_latency_ms` starts at the steady-clock scheduled arrival and ends when the decision is made, including scheduler delay, queue wait and image decode. `artifact_latency_ms` starts after the decision and covers asynchronous persistence; it is never added to decision latency. A completed GPU event is required before the model time or decision is emitted.

The 20 FPS scheduler on Windows uses a high-resolution waitable timer when the OS supports it and records `scheduler_wait` in `snapshot.json`; otherwise it falls back to `std::this_thread::sleep_until`. The first 1800-second run with standard sleep completed 36000 frames but had P95 40.3861 ms and elapsed 1799.983 seconds, so it did not pass. The revised scheduler includes the frame at the 1800-second endpoint. A separate full run (`runs/soak-highres/summary.json`) completed 36001 frames in 1800.026 seconds, with decision P95 26.7411 ms and one timeout. The before/after change is isolated to scheduling and does not change model or threshold selection.

The default operating target is 20 FPS, decision P95 at most 40 ms and timeout ratio at most 1%. Benchmarks use 100 warmups and 1000 steady-state iterations, three independent repeats with profiling disabled, followed by a separate profiled run. Cold startup and TensorRT engine build are reported separately. Keep the same model hash, input size, backend and precision when comparing CPU versus CUDA postprocessing. Keep the same model/backend/postprocess when comparing precisions. Save raw `events.jsonl`, `benchmark.jsonl`, ORT profile and `summary.json`; report P50/P95/P99 and counts rather than only an average. Synthetic Conv results are engineering tests and cannot be used as target-model performance evidence.

Scores use the maximum of the raw fused anomaly map and are not probabilities. The validation image threshold is selected under FPR budget 0.10 with deterministic tie-breaking. Final test uses frozen candidates and thresholds, reports TP/FP/TN/FN, AUROC, noninterpolated Average Precision, FNR and FPR, plus prediction coverage and separate ERROR count. Duplicate replay images contribute one quality sample only. Pixel IoU remains null until a justified pixel threshold and mask protocol are recorded. Confidence intervals must use unique source images, never repeated replay frames.

The 1800-second replay checks stability and queue/error behavior. It does not add new quality images. Material changes to resize, color, antialiasing, normalization or score reduction require a separate validation candidate before test use. A TensorRT provider assignment and QDQ graph are prerequisites but do not establish INT8 execution; `tools/verify_trt_int8.py` inspects an engine cached from the same target model and records the actual layer types and precision evidence.

The independent TensorRT experiment uses a separate directly built engine because the ORT TensorRT cache exposes layer names only. `tools/verify_trt_route.py` checks the derived-model/source equivalence, detailed INT8 convolution weights/inputs/tactics, runtime layer matches, 69 unique validation outputs and hashes; it never reads final test. The same-backend timing in `reports/trt_engine_benchmark_with_transfers.json` supplies the same validation image to each engine, enables transfers, uses 1000 ms warmup and 1000 measured iterations per round, and alternates order over three rounds. It separately reports GPU compute and engine iteration latency including H2D/D2H. TensorRT permits TF32 for the FP32 engine by default. These measurements exclude preprocessing, scheduling and postprocessing and cannot be substituted for C++ `decision_latency_ms`. The earlier no-transfer probe is retained as exploratory raw evidence only.

The later C++ TensorRT comparison in `reports/trt_cpp_pipeline_benchmark.json` uses the same two engines, the same validation image, 100 warmups and 1000 measured calls per round, and alternating order across three rounds. Its `pipeline` wall time includes OpenCV preprocessing, transfers, inference and CUDA postprocessing, but excludes image decode, scheduler and queue. `reports/trt-cpp-benchmark-audit.json` cross-checks all raw hashes against both routes' validation quality. The FP32 TensorRT timing comparator fails the frozen-threshold FNR gate; the result is a measured timing ratio, not a comparison of two quality-qualified production routes or a decision-latency speedup. The INT8 30-minute `decision_latency_ms` and replay event audit are reported separately.
